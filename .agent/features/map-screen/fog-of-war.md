# Map Screen Fog of War

> A single PNG mask painted by the DM over the active battlemap: black hides, transparent reveals. Edited in a dedicated modal (brush / rectangle / grid-cell / room-reveal, reveal or cover), rendered on the map screen inside the stage transform, and persisted per map as a vault sidecar PNG keyed by the map's `/vault/` URL — note images and Hydrus-cached files alike. A companion Walls editor in the same modal defines line segments that block line-of-sight; walls are persisted as a JSON sidecar and broadcast as `map-walls` so vision holes are clipped to LoS on the client. The Walls tab supports importing walls from a UVTT file (`.dd2vtt`, `.uvtt`, `.df2vtt`, `.json`) or from a Foundry module `.zip` (Czepeku/Foundry format). A Rect wall tool lets the DM drag a rectangle that becomes four independent wall segments.

## Requirements

1. While a map is active, the Map Screen section shall render a Fog button that opens `MapFogModal`; the label reads `Fog ●` when the map has fog and `Fog` otherwise.
2. The fog mask shall be an offscreen canvas of width `1024` (`FOG_RESOLUTION`) and height `max(1, round(1024 × naturalHeight/naturalWidth))`; black = hidden, transparent = revealed. A map with no stored fog starts fully transparent.
3. The modal shall expose two tabs (`dm-fog-tabs`): **Fog** and **Walls**. Switching tabs rebuilds the toolbar and reattaches drawing listeners; the stage and overlay are shared.
4. The Fog tab shall offer Reveal/Cover modes × Brush (stamped circles sized by a 2–15% slider), Rectangle (dashed marquee — `#7bd88f` reveal / `#f97583` cover — committed on mouseup), Grid cell (whole cells snapped via `gridCellRectAt`), Grid rect (same dashed marquee as Rectangle but the committed rect is snapped to whole grid cells), and Room tools, plus Reveal All and Cover All. Reveal composites with `destination-out`; Cover paints opaque black with `source-over`. The mask renders at 0.55 alpha in Fog mode (0.25 in Walls mode) so the DM sees the map beneath.
5. The Room tool (Fog tab) shall: (a) build the `blocked` mask via `buildBlockedMask(walls, fw, fh, fogScale, pxPerSquare, blocksSight)` — which rasterizes the admitted (sight-blocking) walls at fog resolution, reads `getImageData`, and seals the mask's 1px outer border (the map edge acts as a wall, mirroring how `visibilityPolygon` closes with the bounds rect) — then call `floodRegion(blocked, fw, fh, fx, fy)`; (b) if `floodRegion` returns null show `new Notice("That point is inside a wall")` and return; (c) otherwise paint the region — via `regionToCanvas(region, fw, fh)` — onto the fog canvas via `applyMode` + `drawImage`, call `redraw()` and `commit()`.
6. When a stroke completes (mouseup), when Reveal All / Cover All is clicked, or when the Room tool fires, the modal shall call `commitFog`, which re-encodes the mask as a PNG data URL, writes the sidecar, and broadcasts `map-fog { dataUrl, opacity: mapFogTvOpacity }`.
7. The sidecar shall live at `.dm-screen/fog/<tail>-<fnv1a(mapUrl)>.png`, where `<tail>` is the sanitized last 60 characters of the decoded vault path (fallback `x` when sanitization strips everything) — deterministic per map URL, identical for note-image and Hydrus-cached maps.
8. When a map is applied, `setVaultMap` shall load the fog sidecar into `fogDataUrl` (or null) and the walls sidecar into `walls`, then broadcast `map-fog` and `map-walls` alongside the other map messages.
9. When the map client receives `map-fog` with a data URL, it shall validate it with `safePlayerUrl(url, "image")` and composite into `#map-fog`: draw the fog image at natural size, then erase each active vision shape via `eraseVisionWithWalls`. Canvas display is set to `block` at the payload opacity; `dataUrl: null` clears and hides the canvas. Rejected URLs are logged via `console.warn` and skipped.
10. `eraseVisionWithWalls(ctx, vision, scale, pxPerSquare, walls, mapWidth, mapHeight, dimAlpha=0.5)` shall: if no wall `blocksSight`, fall through to `eraseVision`; otherwise compute `visibilityPolygon` from the vision centre, clip the canvas to the polygon path, then call `eraseVision` inside the clip; skip when the polygon has fewer than 3 points. `dimAlpha` controls the dim zone opacity: 0.5 for live rendering (darkened reveal), 1.0 for baking (full reveal).
10a. `eraseVision(ctx, vision, scale, pxPerSquare, dimAlpha=0.5)` shall erase two zones under `globalCompositeOperation = "destination-out"`: the bright zone out to `sizeFt` is fully revealed (`rgba(0,0,0,1)`); the dim zone from `sizeFt` to `sizeFt + dimFt` is erased with `rgba(0,0,0,dimAlpha)` (0.5 for live rendering darkens it, 1.0 for baking fully reveals it). `featherFt` applies only to the outer edge of the outermost zone; the feather gradient starts at the outermost zone's alpha (1.0 when `dimFt` is 0, `dimAlpha` when `dimFt` > 0) and fades to 0. When `dimFt` is 0 the dim zone is not drawn. Line of sight from walls clips both bright and dim zones.
10b. `normalizeVision(v: MapVision): MapVision` shall return a copy of the vision with `dimFt` defaulted to 0 when missing, negative, NaN, or a non-number. Map message handlers and cache restore apply this to untrusted or legacy payloads.
11. When the map client receives `map-vision` with a `visions` array, it shall store the list and recomposite the fog canvas immediately (no-op when no fog image is loaded).
12. When the map client receives `map-walls` with a `walls` array, it shall store the list and recomposite the fog canvas immediately.
13. `map-clear` shall clear and hide the fog canvas and reset visions and walls on the client; `stopMap` resets `fogDataUrl` and `walls` to null/empty — sidecars are never deleted, so re-adding the same map restores them.
14. `restoreFromCache` shall recover `fogDataUrl` from the `map-fog` slot and `walls` from the `map-walls` slot; `republish()` shall re-broadcast `map-fog` and `map-walls` while a map is active.
15. When `mapFogTvOpacity` changes in settings, the plugin shall re-broadcast fog through the open DM Control Panel so connected screens update live.
16. When the modal closes during an in-progress drag, the document-level mousemove/mouseup listeners shall be removed (`cleanupDrag`).
17. The overlay shall draw all walls scaled by `fogScale`: plain walls `#f5d90a` lineWidth 3; door walls `#44aaff`; open doors dashed (`setLineDash([8,6])`). In Walls mode, if a chain draft is active, a dashed preview segment shall be drawn from the anchor to the current cursor.
18. The Walls tab shall offer Wall, Door, Erase, Toggle door, and Rect tools, plus a Snap checkbox.
19. Wall and Door tools shall use chained left-click drawing: the first click sets the anchor; each subsequent click appends a segment from the anchor to the clicked point (snapped to grid intersections when Snap is checked, ignored when zero-length) and advances the anchor; right-click (contextmenu, preventDefault) ends the chain without adding a segment.
19a. The Rect tool shall use a drag gesture: mousedown records the natural-coord anchor (snapped if Snap is checked); mousemove draws a dashed `#f5d90a` rectangle preview on the overlay; mouseup computes the axis-aligned bbox (min/max of the two natural corners, snapped if Snap on), discards degenerate rects (zero width or height), and appends four independent plain walls (top, right, bottom, left) to `this.walls`, then calls `commitWalls`. Document-level mousemove/mouseup listeners are registered on mousedown and cleaned up in `cleanupDrag`.
20. The Erase tool shall remove the nearest wall whose point-to-segment distance (in natural coords) is less than `12 / fogScale`; Toggle door shall flip `open` on the nearest door wall within the same hit radius. Both commit immediately via `panel.commitWalls`.
21. `broadcastWalls()` shall broadcast `{ type: "map-walls", payload: { walls } }`; `commitWalls(walls)` shall update `this.walls`, write the walls sidecar (at `wallsSidecarPath`), and call `broadcastWalls()`; `republish()` shall call `broadcastWalls()` alongside `broadcastFog()` — an empty walls list is a valid signal for late joiners.

## UVTT import

28. The Walls tab toolbar shall include an **Import UVTT** button. Accepted file types: `.dd2vtt`, `.uvtt`, `.df2vtt`, `.json`. On click the button opens a native file picker; on file selection the file is read as text and JSON-parsed.
29. `parseUvttWalls(doc: unknown): UvttParseResult` (in `src/map/uvtt.ts`) shall validate the document at the boundary: `resolution.map_size.x/y` must be finite positive numbers; `resolution.pixels_per_grid` must be a finite positive number; missing fields throw `new Error("Not a UVTT file (missing resolution/pixels_per_grid)")`. `line_of_sight`, `objects_line_of_sight`, and `portals` default to `[]` when absent.
30. `parseUvttWalls` shall convert polylines: every consecutive pair of points in `line_of_sight` and then `objects_line_of_sight` → `{ x1, y1, x2, y2 }` where each coordinate is `(point.coord − map_origin.coord) × pixels_per_grid`. Zero-length segments and polylines with fewer than 2 points are skipped. Portals with ≥ 2 bounds points → `{ x1: first.x, y1: first.y, x2: last.x, y2: last.y, door: true }` (same coordinate transform); `open: true` is added when `portal.closed === false`. Result order: `line_of_sight` segments, then `objects_line_of_sight` segments, then portal walls.
31. On any parse error, `importUvttDoc` shall show `new Notice(\`UVTT import failed: ${message}\`, 6000)` and return without modifying walls.
32. On success, the parsed walls shall be scaled to the displayed map by `panel.importWalls(result, sourceLabel)` (in `MapScreenPanel`, shared by the UVTT, Foundry-file and Hydrus imports): `scale = activeMap.naturalWidth / (result.gridSquares.x × result.pixelsPerGrid)`. Every wall coordinate is multiplied by `scale`; `commitWalls` receives the scaled list and `importWalls` returns it, so the modal replaces `this.walls` with it and redraws the overlay.
33. On success, `importWalls` shall configure the map grid via `applyGridConfig(pxPerSquare, 0, 0)` where `pxPerSquare = activeMap.naturalWidth / result.gridSquares.x` (integer when the division is exact, otherwise rounded to 2 decimal places). `applyGridConfig` sets `state.pxPerSquare / gridOffsetX / gridOffsetY`, calls `broadcastConfig()`, `persistState()`, and `host.render()`.
34. On success, `importWalls` shall show `new Notice(\`Imported ${walls.length} walls (${doors} doors) — grid set to ${pxPerSquare} px/square\`)` where `doors` is the count of walls with `door: true`.

## Foundry module import

35. The Walls tab toolbar shall include an **Import Foundry** button. Accepted file type: `.zip`. On click the button opens a native file picker; on file selection the file is read as `ArrayBuffer`, converted to `Uint8Array`, and passed to `importFoundryZip`.
36. `importFoundryZip(zipBytes: Uint8Array)` shall: unzip via `unzipSync` (fflate) with a filter that admits only `.db`, `.log`, `.ldb` entries (large image assets are NOT inflated); pass the resulting entry map to `collectFoundryScenes`; on a bad zip show `new Notice(\`Foundry import failed: ${message}\`, 6000)` and return; when no scene has walls show `new Notice("Foundry import failed: No scene with walls found in module", 6000)` and return; otherwise resolve the scene with `panel.pickFoundryScene(scenes)` (requirement 41a) and, unless the picker was dismissed, import it with `panel.importWalls(sceneImportResult(scene), ...)`.
37. `collectFoundryScenes(entries: Record<string, Uint8Array>): FoundryScene[]` (in `src/map/foundry.ts`) shall: gather scene documents from every `.db` entry via `parseNedb` (TextDecoder, walls inline); gather scene documents from every `.log`/`.ldb` entry under a `packs` path via `parseLeveldbEntries` + the embedded-collection assembly (requirement 39a); and return every document `foundrySceneToWalls` accepts. `sceneImportResult(scene)` shall return `{ walls: scene.walls (in scene px), gridSquares: { x: width/gridSize, y: height/gridSize }, pixelsPerGrid: gridSize }`.
38. `parseNedb(text: string): unknown[]` shall split on newlines, `JSON.parse` each non-empty line, ignore parse failures, and skip docs that carry a `$$deleted` key.
39. `parseLeveldbEntries(bytes: Uint8Array): LeveldbEntry[]` shall parse the LevelDB write-ahead-log: 32768-byte blocks; each record header is `crc(4 LE) + length(2 LE) + type(1)` (CRC is not verified); types 1=FULL (emit immediately), 2=FIRST / 3=MIDDLE / 4=LAST (concatenate, then emit); stop a block when a zero-length/zero-type header appears; for each reassembled record, locate the first `{`, parse the balanced top-level JSON object via brace-depth walking (respecting strings and escapes), and recover the document's LevelDB key from the record bytes preceding the value (`!scenes!<id>` or `!scenes.walls!<sceneId>.<wallId>`). `parseLeveldbLog` is `parseLeveldbEntries(...).map(e => e.doc)`.
39a. The LevelDB embedded-collection assembly shall group `!scenes.walls!<sceneId>.<wallId>` documents by their key's `sceneId` and, for each scene document that lacks inline wall geometry (its `walls` array holds ID strings, not objects with `c`), replace `walls` with the wall documents grouped under the scene's `_id` — yielding scene docs in the inline shape `foundrySceneToWalls` consumes.
40. `foundrySceneToWalls(scene): FoundryScene | null` shall: require numeric `width`, `height`, array `walls`, and `grid` that is either a number or `{ size: number }`; subtract the padded-scene inset from every wall coordinate — `padX = ceil(width × padding / gridSize) × gridSize`, `padY` likewise (Foundry stores `padding` explicitly, default 0.25; an absent field is treated as 0 so non-Foundry callers are not shifted) — so walls land relative to the background image's top-left; filter walls that do not block sight (`sense === 0` in older Foundry, `sight === 0` in newer); skip zero-length walls (`x1===x2 && y1===y2`); for `door > 0` produce `{ x1,y1,x2,y2,door:true, ...(ds===1 ? {open:true} : {}) }`; carry the scene's background path as `background` (`background.src` in newer modules, `img` in older ones, `""` when neither); return null when no valid walls or invalid dims.
41. `chooseScene(scenes, target: SceneTarget): SceneChoice` shall pick the scene whose walls belong to a map of `target.width × target.height` carrying `target.tags`. It shall (a) keep the scenes whose aspect ratio is within `|ln(sceneRatio / mapRatio)| ≤ 0.03` of the map's, or every scene when none is; (b) tokenize with `sceneTokens` — split camelCase, lowercase, split on non-alphanumerics, drop one-letter words, words containing a digit (scene sequence codes such as `03a`) and the stop words `the`, `of`, `and`, `a`, `an`; (c) score each scene against the tokens of its `name` plus the file name of its `background`: one point per word of the map's `name:` tags present, and, for each tag without a namespace, the tag's word count when every one of its words is present (namespaced tags other than `name:` are ignored); (d) order the candidates by score, then base name (no `(`) first, then most walls; and (e) return the top scene as `scene` only when every `name:` word is present in it and no candidate with the same score carries a different wall set (walls compared as sorted rounded coordinates, so day/night copies of a room are not a conflict) — otherwise `scene` is null. `candidates` always holds the ordered list.
41a. `MapScreenPanel.pickFoundryScene(scenes)` shall call `chooseScene` with the active map's natural size and `activeMapTags` (the Hydrus tags passed to `setVaultMap`, empty for note images) and resolve with the chosen scene; when the choice is ambiguous it shall open `FoundrySceneModal`, a fuzzy picker over the ordered candidates (each item reads `<name> — <walls> walls, <width>×<height>`), and resolve with the picked scene or `null` when the picker is dismissed.

## Automatic import from Hydrus

41b. When `setVaultMap` is called with a `hydrusHash`, it shall, after the map is shown, call `offerFoundryWalls(url)` without awaiting it. `offerFoundryWalls` shall return silently when `buildHydrusClient()` returns null, when the lookup throws (logged with `debugWarn`), or when no module is found.
41c. `findFoundryModules(client, tags)` (in `src/hydrus/foundryModules.ts`) shall, for each `name:` tag of the map, call `searchFiles([nameTag, FOUNDRY_MODULE_TAG], 8)` with `FOUNDRY_MODULE_TAG = "type:foundry module"`, merge the hashes, and return `getFileMetadata` for at most 8 of them; a map without a `name:` tag makes no request.
41d. When modules are found, `offerFoundryWalls` shall open `FoundryImportConfirmModal` ("Foundry module found": `Hydrus has a Foundry module for "<name>". Import its walls and grid?`, plus `This replaces the <n> walls this map has.` when the map already has walls) with **Skip** and **Import** buttons; closing it counts as Skip. On Import it shall read the scenes with `loadModuleScenes`, show `new Notice("Foundry import: the module has no scene with walls", 6000)` when there are none, otherwise resolve the scene with `pickFoundryScene` and import it with `importWalls`. After every await it shall stop when the active map's URL is no longer the one it started for, so a map switched meanwhile never receives another map's walls.
41e. `loadModuleScenes(client, modules)` shall read each module with `readZipEntries((start, end) => client.getFileRange(hash, start, end), size, /\.(db|log|ldb)$/i)` and pass the entries to `collectFoundryScenes`; a module that cannot be read is skipped with `debugWarn`.
41f. `readZipEntries(read, size, wanted)` shall fetch the last `22 + 65535` bytes, locate the end-of-central-directory record, read the central directory (from that tail when it lies inside it, otherwise with one more ranged read), and for each entry whose name matches `wanted` read its 30-byte local header and then exactly its compressed bytes, inflating method 8 (`inflateSync`) and passing method 0 through; other compression methods are skipped. When the first read answers with the whole file (`partial: false`, a server that ignores `Range`) or the archive is Zip64, it shall fall back to `unzipSync` over the whole file with the same filter. A file without an end-of-central-directory record throws `not a zip archive`.

## Broadcast / IPC

| Message type | Direction | Payload | When |
|--------------|-----------|---------|------|
| `map-fog` | DM → map | `{ dataUrl: string \| null, opacity: number }` | Map apply; every completed fog edit; opacity setting change; `republish()` |
| `map-vision` | DM → map | `{ visions: MapVision[] }` (each vision may carry `followsView`, `viewOffsetX`, `viewOffsetY`, `label`, `color`; the map screen ignores all but `followsView`'s effect on `x/y`) | Any time active vision shapes change — including a view-bound vision carried along by `syncBoundVisions` on pan; client recomposites immediately |
| `map-walls` | DM → map | `{ walls: MapWall[] }` | Map apply; every wall edit; `republish()` |

Full channel routing in `../player-server/websocket-protocol.md`.

## DM vision controls

The Map Screen section exposes a Vision subsystem below AoE Overlays while a map is active.

22. The DM panel shall render a Vision section (via the reusable `renderVisionSection(container, map, onChange)`, shared with the Explore modal's side panel) with an Add Vision menu (Circle 30 ft / Square 30 ft / Lights…); new visions spawn at the map center with `sizeFt: 30`, `dimFt: 0` and `featherFt: 5`. `MapVision` carries `dimFt` (dim light radius in ft, defaults to `0` when missing or invalid on restore) and optional `followsView`, `viewOffsetX`, `viewOffsetY`, `label` and `color` fields.
22a. Lights… shall open `LightSourceModal`, a fuzzy search over `LIGHT_SOURCES` (each item reads `<name> — <bright> ft bright, +<dim> ft dim`); picking one adds a circle vision at the map center with `sizeFt = brightFt`, `dimFt`, `featherFt: 5` and `label = name`. `LIGHT_SOURCES` shall contain every 5etools item and spell whose text gives a radius of bright light plus an additional radius of dim light (or dim light only, as `brightFt: 0`), taking the PHB entry over XPHB over any other source when several share a name, plus the hand-added `Darkvision 60 ft` (0/60) and `Darkvision 120 ft` (0/120), sorted case-insensitively. Cones (Bullseye Lantern and similar) are excluded.
22b. When visions exist the header shall render a group toggle (`.dm-map-vision-group`, glyph `🔗`, `aria-pressed` mirroring `visionGroup`, `dm-fog-active` when on). `visionGroup` lives on the panel for the session and starts off; because the Explore Vision window renders the same section, the toggle appears in both places.
23. When visions exist the section shall also render a Bake into fog button and a Clear All button; Bake composites all active visions onto the persistent fog mask (building a canvas, drawing the existing fog if present, erasing each vision with `eraseVisionWithWalls` using the current `walls`, then calling `commitFog`) and clears the live vision list; Clear All empties the list and broadcasts immediately.
24. Each vision shall render as a collapsible control card (via `renderControlCard` from `src/views/controlCard.ts`): the collapsed summary shows the swatch (`vision.color`, default `DEFAULT_VISION_COLOR` `#ffd23f`), the label (`vision.label`, falling back to the shape), shape icon, size summary (`30 ft` when `dimFt` is 0, otherwise `<bright>/+<dim> ft` e.g. `30/+20 ft`), and a remove ✕. Clicking the summary (except the ✕) expands the card; only one vision is expanded at a time. The expanded details expose: a Label text input (an empty value clears `label`) with a colour picker (`.dm-map-vision-label`, `.dm-map-vision-color`), shape select (circle / square), Bright (sizeFt, min 0 step 5, so darkvision can keep a 0 bright radius), Dim (dimFt, min 0 step 5), Feather (featherFt, min 0 step 5), and a bind-to-view toggle button (`.dm-map-vision-bind`, glyph `⦿`, `dm-fog-active` when bound), all laid out on wrapping rows. Each change broadcasts `map-vision` immediately.
24a. The bind-to-view toggle shall flip `vision.followsView`. Turning it on leaves the vision where it is and records its offset from the players' viewport centre with `anchorToView` (`viewOffsetX = x − panX`, `viewOffsetY = y − panY`); turning it off deletes both offsets. `syncBoundVisions(immediate?)` re-places every `followsView` vision with `followView` at `(panX + viewOffsetX, panY + viewOffsetY)` — a missing offset counts as 0 — clamped to `[0, naturalWidth] × [0, naturalHeight]` while the stored offset is kept, broadcasts when any moved, and returns whether any moved; it is called from `applyExplorePan` and from the pan-preview `applyPan`. With the view centre at (400, 500) and a bound light at (500, 600), moving the view to (600, 800) puts the light at (700, 900).
25. Each vision shall carry a draggable dot (`.dm-map-vision-dot`) in the pan preview positioned at `(x/nw, y/nh)` percent; left-drag moves the vision (same `deltaToMap` pattern as AoE dots), throttled broadcast during drag, immediate on mouseup. The dot's fill is the vision's colour and its tooltip names its label.
25a. A vision drag (pan preview and Explore markers alike) shall move `visionDragTargets(visions, dragged, visionGroup)`: only the dragged vision when group mode is off or the dragged vision is bound to the view, otherwise every vision without `followsView`. A dragged bound vision is re-anchored (`anchorToView`) at every step, so its new offset from the view centre is the one later pans keep. `moveVisions(targets, starts, dx, dy, nw, nh)` applies the same delta, measured from the drag start, to every target, clamped once for the whole set so each stays within `[0, nw] × [0, nh]` and the formation keeps its shape; every vision dot is re-placed each step and the move still emits one throttled `map-vision` broadcast. When `applyPan` reports a bound vision moved (`syncBoundVisions()` returned true), the preview shall both `redrawAoes()` (the dashed outline) and re-run each vision dot's positioner, so the `.dm-map-vision-dot` marker follows the viewport — not just the canvas outline.
26. The `redrawAoes` canvas shall draw dashed vision outlines at 2px lineWidth: the bright zone edge (`sizeFt * (pxPerSquare/5) * s` radius/half-side) with `setLineDash([6,4])` in the vision's colour (default `#ffd23f`), and, when `dimFt > 0`, a second dim zone outer edge (`(sizeFt + dimFt) * (pxPerSquare/5) * s`) with `setLineDash([3,3])` in the same colour at `88` alpha (semi-transparent to distinguish it from the bright edge).
27. `broadcastVisions(immediate?)` shall follow the same throttle pattern as `broadcastAoes`; `setVaultMap` resets `this.visions = []` and calls `broadcastVisions(true)`; `stopMap` resets `this.visions`; `restoreFromCache` recovers from the `map-vision` slot; `republish()` re-broadcasts visions when non-empty.

## Exploration Mode

A dedicated table-play surface, separate from the Fog editor: no drawing toolbar. Left-click on the map alternates two gestures (toggle a door, reveal/cover a room); three floating, draggable, minimizable windows (AoEs, Vision and Combat) hold the DM panel's control sections, and the bar carries the scale and grid toggles. On top of that the DM can drag the players' viewport window (physical mode, unless the view is locked) and move the AoE and vision markers. Holding Shift momentarily focuses the door/room gestures by letting clicks pass through every marker. Doors, fog, AoE, vision, and view moves all broadcast through the existing `commitWalls` / `commitFog` / `broadcastAoes` / `broadcastVisions` / `applyExplorePan` methods — no new message types.

42. The Map Screen section header shall render an **Explore** button (`dm-explore-open-btn`, beside the section title, visible even while the section is collapsed and disabled while no map is active — `overview.md` requirement 9a) that opens `MapExploreModal`; the modal class is `dm-explore-modal`, sized ~96vw × 96vh.
43. `MapExploreModal(app, plugin, panel, map)` shall lay out (inside the `dm-explore-content` wrapper on `contentEl`) a `dm-explore-bar` (top) over a `dm-explore-body` row that holds the full-width map `dm-explore-stage`. The stage shows the map media (image via `getResourcePath`, video autoplay/muted/loop) inside a `dm-explore-inner` box that carries the map's aspect ratio, is centred, and is rotated by the map's configured `panel.state.rotation` (0/90/180/270) via a CSS `rotate()` transform (sized so the rotated box fits the stage). It shall load `panel.fogDataUrl` into a 1024-wide fog canvas the same way `buildFogCanvas` does, overlay a `dm-explore-overlay` canvas at fog resolution, and add a pointer-transparent `dm-explore-markers` layer above it (only dots and the viewport rect capture pointer events). The overlay draws the current fog at 0.5 alpha, then the hover highlight, then — while `panel.state.showGrid` is on — the grid lattice as 1 px lines in `gridColor` at `gridOpacity`, placed by `gridLinePositions(0, gridOffsetX|Y, pxPerSquare, fogScale, overlay width|height)` (the same lattice the map screen draws, `scale-and-grid.md` requirement 7; the inner box's CSS rotation carries it to the view rotation), then each panel AoE via `renderAoe(octx, aoe, fogScale, 0, 0, pxPerSquare, 0)`, then vision range outlines in each vision's colour (bright edge dashed at `sizeFt × (pxPerSquare/5) × fogScale`, dim outer edge when `dimFt > 0` dashed at `88` alpha at `(sizeFt + dimFt) × (pxPerSquare/5) × fogScale`), then walls faintly (0.35 alpha; plain `#f5d90a`, doors `#44aaff`), then door markers. That repaint walks the fog image and every AoE, vision, wall and door, and hover and marker drags fire it per pointer move, so it is coalesced to at most one per animation frame and cancelled on close (`scale-and-grid.md` requirement 6f). The map image is the shared downscaled copy of `scale-and-grid.md` requirement 6g. Three `FloatingWindow` instances (`aoes`, `vision` and `combat`) float over the stage, positioned and minimized per `settings.exploreWindows[id]` (default: AoEs and Vision in the top-right corner, side by side, 260 px wide each; Combat in the top-left corner, 320 px wide; 12 px margin, not minimized). A `ResizeObserver` on the stage calls `clamp()` on every window to keep them inside the stage bounds on resize. The windows are destroyed and the observer disconnected on close.
43a. The floating windows shall render the AoE and Vision controls by calling `panel.renderAoeSection(aoesWindow.body, map, refresh)` and `panel.renderVisionSection(visionWindow.body, map, refresh)` — the same full collapsible control cards as the DM panel (add/clear, shape, size, colour, opacity, rotation, feather, bind-to-view, remove). The `refresh` callback rebuilds the window bodies, re-renders the on-map markers, and repaints the overlay, so an edit made in the windows is reflected on the map immediately. Each window's header holds its title ("AoEs" / "Vision") and a minimize/restore button (`–` / `▢`). Minimizing collapses the window to its header; restoring brings back the body. Dragging by the header moves the window (position clamped to the stage bounds), using pointer capture. `onChange` fires on drag end and minimize toggle, persisting the window's `{ x, y, minimized }` state to `settings.exploreWindows[id]` via `saveSettings`. Window body has `overflow-y: auto` and `overflow-x: hidden`.
43b. The Combat window shall mirror the DM panel's COMBAT section: the modal passes it to `panel.registerCombatMirror(combatWindow)`, and the DM panel renders the same combat body into the window body (tabs, active-combat name row with the tracker scale buttons, manual/plugin tracker or the D&D Beyond panel) and its Live toggle into the window header's extra slot, on registration and on every panel render (`../combat-tracker/overview.md` requirement 27). Inside the window the manual tracker's name field flexes (`min-width: 0`) so the add-combatant row fits the 320 px window without horizontal overflow.
44. Each door shall draw a filled circle marker at its segment midpoint — `#7bd88f` when open, `#888888` when closed — of radius `max(10, pxPerSquare × fogScale × 0.35)`. `fogScale = fogCanvas.width / map.naturalWidth`.
45. Overlay client coordinates shall be converted to fog/map space through the map rotation: `toFog`/`deltaToMap` read the overlay's own bounding rect (centre + rotation-unrotated dimensions) and apply `rotatePoint(..., (360 − rotation) % 360)`, so hit-testing and marker drags stay correct under a rotated view. `deltaToMap` returns `null` when the overlay reports a zero dimension and every marker drag returns early on it, so a drag over an overlay that cannot be measured is inert instead of resolving to ±Infinity and clamping the marker onto the map bounds (`scale-and-grid.md` requirement 6c). Each marker drag holds the DM panel's drag lock through `panel.beginPanelDrag()` for the duration of the gesture (`scale-and-grid.md` requirement 6e). The modal registers an overlay repaint with `panel.registerOverlayRepaint()` so a size, width or opacity edit made in the sidebar re-places the on-map markers and repaints the overlay in place, and drops the registration on close (`aoe-overlays.md` requirement 8).
46. A left mousedown on the overlay shall first hit-test doors: the nearest door whose midpoint (natural coords) is within `(doorRadius + 6) / fogScale` of the click toggles its `open` via an immutable update (`this.walls.map(w => w === hit ? { ...w, open: !w.open } : w)`) and calls `panel.commitWalls([...])`; the original wall object is not mutated. A door hit consumes the click (no fog toggle).
47. When no door is hit, the click shall auto-toggle the clicked room's fog: sample the fog canvas alpha at the clicked fog pixel — if revealed (`alpha < 128`) paint the room region opaque black (`source-over`), otherwise erase it to transparent (`destination-out`) — then call `panel.commitFog(fogCanvas.toDataURL("image/png"))`.
48. The room region shall be computed by `computeRegion(fx, fy, fogScale)`: flood the memoized all-walls blocked mask via `floodRegion`. The mask is built by `buildBlockedMask(walls, fw, fh, fogScale, pxPerSquare, () => true)` — rasterizing **all** walls (doors included, regardless of `open`) as blocking lines and sealing the 1px border — and cached against the current `walls` reference + `fogScale`, so hover and click reuse one rasterization until the walls list changes (a door toggle drops the cache). Doors are ALWAYS room boundaries in exploration (this differs from the Fog Room tool of req 5, which admits only `blocksSight` walls); open/closed affects only the player-TV LoS via the `map-walls` broadcast. When `floodRegion` returns null (a wall pixel) show `new Notice("That point is inside a wall")` and do nothing.
49. On mousemove over the overlay, when the hovered fog cell changes, the modal shall recompute that cell's region and draw a subtle green highlight (`rgba(123,216,143,0.25)`) on the overlay so the DM sees which room will toggle; mouseleave clears the highlight. The hovered cell's region is memoized (keyed by the floored fog cell) so the subsequent click reuses it when it lands in the same cell, and the tint is produced by filling the `regionToCanvas` mask with the highlight colour via `source-in`.
50. The top bar (`dm-explore-bar`) shall offer **Reveal All** (clear the fog canvas), **Cover All** (fill it opaque black), a **lock** button (`dm-explore-lock-btn`, lucide `lock`/`unlock`, `dm-fog-active` when locked), **Scale: physical 1″ / Scale: fit screen**, **Grid: on / Grid: off**, and **Exit** (close the modal). The Scale button calls `panel.toggleScaleMode()`, relabels itself and refreshes the windows, markers and overlay, so the players'-viewport rectangle of requirement 51 appears or disappears at once; the Grid button calls `panel.toggleGrid()`, relabels itself and repaints the overlay (`scale-and-grid.md` requirement 9a). Reveal All and Cover All commit fog like the Fog editor's equivalents. The lock button toggles `panel.viewLocked` (a getter/setter over the shared `previewLocked`) and re-renders the markers.
51. In physical mode the markers layer shall render a players'-viewport rectangle (`dm-map-viewport-rect`), sized and positioned from `panel.playerViewportMapSize()` and `panel.state.panX/panY`. When `panel.viewLocked` is true the rectangle is a passive dashed outline (`dm-explore-rect-locked`, no pointer events) and cannot be dragged. Otherwise dragging it calls `panel.applyExplorePan(panX, panY, false)` (throttled) during the drag and `panel.applyExplorePan(panX, panY, true)` on release, moving only the players' TV window (the DM's own rotated view is untouched). No rectangle is shown in fit mode.
51a. `applyExplorePan` calls `syncBoundVisions`, so any vision with `followsView` moves by the same amount as the view (keeping its offset from the view centre) as the rectangle drags; when at least one bound vision exists the drag also repaints the overlay and re-renders the markers each step, so the lit area and its dot track the viewport live.
52. The markers layer shall render each panel AoE as a draggable anchor dot (`dm-map-aoe-dot`) — and, for non-symmetric shapes, a rotation handle (`dm-map-aoe-rot-handle`) at the shape's tip/mid-edge — mirroring the panel pan-preview: dragging moves/rotates the AoE (`panel.broadcastAoes()` throttled, `panel.broadcastAoes(true)` on release); right-click (contextmenu, preventDefault) removes it via `panel.removeAoe(id)` and re-renders. Each panel vision renders a draggable dot (`dm-map-vision-dot`) that moves the vision — or the whole group, requirement 25a (`panel.broadcastVisions()` / `broadcastVisions(true)` on release). Numeric editing (add, remove, size, feather, colour, bind) happens in the floating windows (requirement 43a); the on-map dots only reposition.
52a. While Shift is held, the markers layer shall carry `dm-explore-focus`, which sets `pointer-events: none` on the layer and all its children, so left-clicks pass through the viewport rect and every AoE/vision dot to the overlay's door/room gestures — a momentary focus that needs no view lock. The class is added on a `Shift` `keydown` (document), removed on its `keyup`, and reset on `window` `blur` (so Shift held during an alt-tab does not stick).
53. On close the modal shall force-detach any in-progress document drag (`activeDrag`), remove its overlay-level mousedown/mousemove/mouseleave listeners and the document `keydown`/`keyup` + window `blur` Shift-focus listeners (`cleanupListeners`), drop the Combat mirror registration, destroy the three windows, then call `panel.refreshPanel()` so the DM panel re-renders with the mutated AoE/vision/pan state — that render also hands the D&D Beyond panel back to the COMBAT section — and empty `contentEl`.

## Non-goals

- Fog on the player screen at `/` (it has its own per-layer fog, `../fog-of-war/overview.md`).
- Line-of-sight computation inside the Exploration modal. Toggling a door commits walls; the player TV recomputes LoS from the `map-walls` broadcast.
- Deleting sidecars from the UI. Stale fog/walls files are cleaned up manually in `.dm-screen/fog/` and `.dm-screen/walls/`.
- Undo history inside the modal. Strokes and wall edits are destructive; Reveal All / Cover All are the fog recovery tools.
- Per-map opacity. `mapFogTvOpacity` is global.
- Regenerating `LIGHT_SOURCES` at runtime or shipping the 5etools data. The catalog is a committed, generated file; rerun `python3 scripts/gen-light-sources.py` after a dnd-library data update.
- Rendering vision labels or colours on the map screen. They are DM-side markers only.
